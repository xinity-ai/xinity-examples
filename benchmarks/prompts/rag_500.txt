Context document one. Streaming inference allows a server to start sending tokens to a client before the full response is ready. The client receives output incrementally as the model generates each token, which reduces perceived latency for the end user. The first measurable interval of interest is the time to first token, often abbreviated as TTFT. It captures the latency between sending the request and receiving the first content chunk in the response stream. A second metric is the average throughput, computed as the number of output tokens generated divided by the wall clock time between the first and last token. These two numbers together describe how a generation feels to a user and how fast a server can produce content under load. Without streaming, a client only observes the total request time and cannot separate prefill cost from decode cost.

Context document two. When several requests are issued at the same time, a server must share its compute across them. The total throughput across the batch tends to grow as concurrency increases, until the device that holds the model becomes saturated. Beyond that point, additional concurrent requests no longer increase total throughput and may instead lengthen the per request latency. A common way to characterise the behaviour of a server is to step through a sequence of concurrency levels, such as one, two, four, eight, and so on, and to record TTFT and throughput at each level. The resulting curve makes it easy to see at which point the server stops scaling and where the latency cost becomes too large for the application. Many servers also expose a fixed maximum batch size beyond which extra requests are queued, which shows up as a sharp increase in TTFT.

Context document three. The OpenAI Python SDK exposes a streaming API on the chat completions endpoint. When the stream flag is set, the call returns an iterator that yields chunks as they arrive. Each chunk carries an incremental delta and an optional usage block. By passing stream options that request the usage block, a client can read the exact number of completion tokens that the server counted, which is the most accurate basis for tokens per second measurements. When the server does not include a usage block in the stream, a client may instead approximate the output length from the number of non empty content chunks, with the caveat that some servers pack more than one token into a single chunk.
